## 2026-07-27 - Never ack a handoff the database didn't keep

**Commit**: `TBD` on `main`

**Summary**: Agent-pushed pieces went missing from the library while their ideas stayed put, and the inbox re-presented work that had already been triaged. Two holes on the import path, both of which end with the last durable copy of a piece being deleted. First, the ack is destructive: it moves the handoff markdown into `.imported/`, which nothing re-reads, so an ack is a promise that the piece is safely on disk elsewhere. `savePiece`, `saveIdea` and `saveResource` caught every IndexedDB failure, logged it, and resolved as if the write had succeeded (`persistence.ts`), and `useAgentInbox` acked unconditionally after awaiting them — so a refused write left the piece in one tab's memory, acked its markdown out of the inbox, and lost it at the next reload. Those three now resolve `false` on a refused write, and the importer withholds the ack for the whole batch unless every write in it landed, leaving the files pending for the next poll (import is idempotent, so the retry is clean). Second, `loadAllIdeas`, `loadAllContentPieces` and `loadAllResources` returned `[]` on a read failure, making "I couldn't read your library" indistinguishable from "your library is empty" — the importer then read the empty maps as "none of this exists yet", re-inserted every pending piece at its *file* status (undoing triage) and acked the source away. Those three now throw, hydration records `loadFailed` on the content store and tells the user to reload, and the importer stands down entirely while it is set. Notes never had this failure mode because `loadAllNotes` reconciles against a localStorage backup; ideas and pieces have no such backup, which is why the same fault presented as ideas surviving (they re-materialize from `idea.json` manifests, which are never acked) while pieces vanished.

**Files**: `src/lib/persistence.ts`, `src/hooks/use-agent-inbox.ts`, `src/hooks/use-persistence.ts`, `src/stores/content-store.ts`, `src/lib/persistence-logger.ts`, `src/__tests__/agent-inbox-ack-safety.test.ts`

**Verification**: 4 new tests driving the real hook against a mocked persistence layer. Two are true regressions, failing on the previous importer and passing now: an ack withheld when `savePiece` resolves `false`, and no polling at all while `loadFailed` is set. The other two pin behaviour that was already correct by accident (a rejected write aborted the poll before the ack) so the new `.catch(() => false)` path can't quietly re-enable the ack. `tsc --noEmit` and `npm run build` clean; suite at 579 of 601, the 22 failures being the same pre-existing `api-*` set (ARI-132), unchanged by this work. Not verified: whether this fault is what actually cost the pieces in the reported incident — that evidence only exists in the user's browser profile, and both holes were confirmed by reading the code rather than by reproducing the loss.

**Related**: `~/bin/dev-process-reaper.py` on olympus was SIGTERM'ing `fragment-app.service` every ~45 minutes (every 30 min of uptime) from 2026-07-26 18:11 onward. `next start` runs a process named `next-server`, which matches the reaper's dev-server patterns, and its only ownership test was membership in a live `hermes-gateway-*.service` cgroup — a production systemd unit is in none, so it read as an orphan. The reaper now skips any process in a managed non-gateway `.service` cgroup. Outside this repo, so not in the file list above.

## 2026-07-27 - Cloud: Postgres, accounts, and cross-device sync (ARI-68, ARI-112, ARI-66, ARI-65)

**Commit**: `6fef563` on `feat/cloud-sync`

**Summary**: Fragment had no cloud for anything a person writes. Every note, idea, piece and snippet lived in one browser's IndexedDB, so the same app opened on a phone, a second browser or the desktop build showed a different, unrelated library, and there was nothing to sync because nothing existed to sync to. The `convex/` backend looked like it might be that cloud and was not: its schema held `users`, `feedback` and `apiLogs` only, no content of any kind, and its `users` table was keyed by `deviceId` rather than by an account, so it could not have identified a person across two devices even in principle. Postgres now holds the durable shared copy while Dexie stays the working copy, which keeps the app fully usable with no account, no network and no server — sync is additive, never a precondition for saving a word. Deltas travel over a monotonic `rev` cursor from one sequence (`where user_id = $1 and rev > $2`), and conflicts resolve last-write-wins per whole record on the client's `updatedAt`. That is the honest trade for prose: two devices editing one note at once is rare, and a merge that interleaved characters from both would corrupt writing in a way the author cannot undo, where losing the older of two versions is recoverable from note history. Every synced collection lands in a single `documents` table with the body as `jsonb`, so the server owns ownership, ordering and transport while the client owns the shape — the Dexie schema can reach v20 and v30 without a server migration behind every field, and pulling changes stays one query rather than one per collection. Signing in to ChatGPT now signs you in to Fragment: the `id_token` the Codex device flow already returned was being decoded and discarded, and is now verified against OpenAI's JWKS before its `sub` is trusted, because a JWT payload is base64 rather than a secret and `sub` is the account key — trusting an unverified one would let a caller sign in as anyone by editing a string. Sessions are server-side rather than stateless so that revoking a lost device actually works, and only a SHA-256 of the cookie value is stored, so reading the sessions table yields nothing presentable. Local changes are captured by Dexie table hooks instead of calls added to each save function in `persistence.ts`: a hook cannot be forgotten by whoever adds the next writer, and a record that silently stops syncing is close to invisible until someone loses work on their second device. Two details that would otherwise be quiet betrayals of a local-first app: provider API keys are stripped from the settings record on the way up and restored from the local row on the way down, so bring-your-own-key does not become a credential store; and a device that has been linked to one account refuses to sync when a different account signs in, rather than guessing whose writing it is holding. Convex is deleted — `identify`, `submitFeedback` and `syncLogs` keep their signatures and now hit `/api/v1` routes on the same Postgres, with feedback attachments on a blob store whose `putBlob`/`getBlob` pair is the seam for S3 or R2.

**Verification**: 20 new unit tests (protocol validation including refusal of unknown collections, `apiLogs` and oversized pushes, and tombstones dropping their body; credential stripping and restoration across a full round trip). 575 of 597 passing, the 22 failures being the same pre-existing `api-*` set (ARI-132), `tsc --noEmit` and `npm run build` clean with all seven new routes registered. Sync itself is verified end to end rather than against mocks, by `npm run verify:sync` against a production build and the real Postgres: 18 checks covering an unauthenticated and a forged session both rejected with 401, an invented collection rejected with 400, device A's writes pulled by device B, a repeat pull at the same cursor returning nothing, B's newer edit reaching A, a stale push from A neither overwriting the winner nor leaving A holding a value it thinks it saved, deletes arriving as tombstones with no content retained server-side, a second account seeing none of the first's documents, a 50-record batch round-tripping, and the same record twice in one push keeping the newer value. The replacement telemetry routes were driven with curl and the rows confirmed in Postgres. Not verified: the Tauri desktop path is source-only here — the bearer-token fallback exists because a SameSite=Lax cookie is never sent from the desktop scheme, but no desktop build was made. No pgvector work yet, so the semantic-search half of ARI-68 remains open.

## 2026-07-26 - Fix: snipping inside an idea did nothing (ARI-187)

**Commit**: `9f26bb0` on `worktree-fix+idea-scoped-snips`

**Summary**: Inside an idea's pieces feed, both snip gestures were dead: dragging a selection to the side did nothing, and clicking **Snip** did nothing. Snippets were hard-scoped to a note. `Snippet.noteId` was mandatory, the Snip Bar rendered only `noteId === activeNoteId`, and the store held a one-note window of the table (`loadSnippetsForNote(activeNoteId)` on every note switch). A short-form piece has no note behind it, so a snip off a piece either got refused outright — `resolveSnipTargetNoteId` found nothing and fired a toast, which is the normal state of an idea whose pieces came from the agent inbox and has no draft — or got filed against whatever unrelated draft happened to be open: written to disk, invisible on screen, and evicted from memory at the next note switch. The drag had it worse and had never worked: the Snip Bar sits collapsed to zero width until something announces a drag is under way, and nothing in the pieces feed did, so the gesture aimed at a panel that wasn't on screen. A snippet now has one of two homes, the note it was cut from or the idea it was cut in (`noteId: string | null` + `ideaId`, new `src/lib/snip-scope.ts`), `order` runs within a home, and the bar shows both homes you're standing in — so the pile of parts stays whole crossing Write ↔ Pieces, and hydration loads note-scoped and idea-scoped snips together. The piece's Snip button always has somewhere to put the text and pins the bar open so you watch it land, the same move the long-form editor already made. Dragging out of a piece is now the editor's gesture — floating card, panel reveal, drop position, source text cut — built on mouse events rather than HTML5 DnD for the reason `editor.tsx` gives (the native ghost can't be overridden in WebKit/Tauri). A textarea can't say where its selection sits on screen, so the hit test runs against the live-markdown mirror, which lays the same string out identically by design; the same mirror answers "which character did I click on" when a click inside a selection needs to place the caret, since taking over `mousedown` means owning that too. Editor snips are tagged with the open idea so they stay in the bar on the pieces side. `resolveSnipTargetNoteId` is gone — the hunt for a note to borrow, and its refusal, both were the bug.

**Verification**: 15 new tests (`snip-scope`, `textarea-selection` offset mapping across styled spans and line breaks, idea-scoped `addSnippet`, per-home ordering, refusal of a homeless snippet); 555 passing with the same 22 pre-existing `api-*` failures (ARI-132); `tsc --noEmit` and `npm run build` clean. Driven against a production build of this branch: reproduced the original no-op first (toast, bar closed, nothing filed), then confirmed the Snip button files and reveals; the drag reveals the collapsed bar mid-gesture, drops at the indicated position, and cuts the source text; snips survive a reload and show in both spaces of the idea; reorder works across mixed homes; a standalone note sees none of the idea's snips; clicking inside a selection places the caret instead of swallowing the click; and the long-form editor's own Snip button and drag-out are unchanged.

## 2026-07-26 - Fix: Draft with Flow left a piece stuck read-only (ARI-184)

**Commit**: `d7e445d` on `main`

**Summary**: Using Flow on a piece could lock it — the only way to edit that piece again was reloading the page. `flowGenerating` holds the textarea `readOnly` while a generation streams, and it was cleared inside `generateStream`'s `onDone` / `onError`. But `useSlashCommand.generateStream` settles **neither** callback when a generation is aborted: both abort paths (an `AbortError` thrown mid-request, and the post-loop `if (!signal.aborted)` guard) return silently, deliberately, since an abort is the caller's own doing and there's no final text to hand back. It also never settles at all if the request just hangs. Either way the flag stayed on and the piece stayed read-only. Three fixes: the flag is now cleared from the returned promise's `.finally`, which runs on every path the hook can take; a **Stop** button appears in the piece footer while generating (mirroring the long-form editor's, and keeping whatever has already streamed); and a card that unmounts mid-stream aborts its own request rather than leaving one running against a piece nobody is looking at. Separately, `⌘⏎` with Flow switched off did nothing at all, which reads as a broken feature rather than an off one — it now points at the setting, and the disabled ⋯ item's tooltip gives the reason. The trap itself is documented on `StreamCallbacks`, so the next caller doesn't flip a flag on and clear it in a callback that may never fire.

**Verification**: reproduced in a browser by intercepting `/api/generate` with a request that never resolves — the piece went read-only with Stop showing; clicking Stop cleared the state, the piece became editable again with no reload, typing was accepted, and the "Stopped — kept what was written" toast fired. `tsc --noEmit` and `npm run build` clean; 541 tests passing with the same 22 pre-existing `api-*` failures (ARI-132).

**Files**: `src/components/shortform/piece-card.tsx`, `src/hooks/use-slash-command.ts`, `docs/FEATURES.md`
## 2026-07-26 - Fix: importing a piece hid it from every agent that reads the inbox

**Summary**: An agent that pushed a piece, then checked its work, was told the piece did not exist. `list_ideas` reported an idea with zero pieces and `get_piece` threw `piece not found`, while the piece sat imported and readable in the app the whole time. The natural next move is to push again, so the failure mode is silent duplication: this was found when a session re-pushed a LinkedIn post it had already delivered, on the evidence of its own verification call. The cause is a layout disagreement about one directory. fragment-mcp's reader reconstructs an idea's pieces from `<ideaId>/` plus `.imported/<ideaId>/`, which is what the transport's own header comment documents; both ack paths instead archived with `path.basename(sourcePath)`, collapsing `<ideaId>/pc_x.md` into `.imported/pc_x.md`. Nothing errored, because flattening is a perfectly valid move: the file just stopped being anywhere the reader looks. Both paths now mirror the source's subdirectory, `ackImportedFile` (web) via `path.relative` + `path.dirname` and `ackTauriImportedFiles` (desktop) by splitting the relPath and creating the subdirectory before the rename. Collision uniquifying still applies, but now within an idea rather than across all of them, so two ideas that each hold a `piece.md` no longer collide into `piece.md` and `piece-2.md` with one of them detached from its origin.

**Verification**: 5 new tests in `src/__tests__/agent-inbox.test.ts` cover the mirrored path, cross-idea same-name isolation, in-idea collision uniquifying, a file at the inbox root, and traversal refusal; 39 pass in that file. Confirmed they actually bite by reverting `server-fs.ts` to the flattening version and re-running: 3 of the 5 fail, and pass again with the fix restored. `tsc --noEmit` clean. Against the live inbox on olympus, after re-filing the already-flattened archive, `list_ideas` went from 0 pieces on both ideas to 4 and 2, matching what is actually on disk. Not verified: the Tauri path is source-only here, exercised by inspection rather than a desktop build.

**Note for operators**: files archived before this fix stay invisible until they are re-filed into `.imported/<ideaId>/`, since the fix only governs new imports. Each piece file carries its own `idea_id` in frontmatter, which is enough to sort them; legacy `idea_title`-only pushes belong at the archive root and should be left alone.

## 2026-07-26 - The Pieces feed is a deck, and markdown formats as you type (ARI-182)

**Commit**: `3b6dc7f` on `main`

**Summary**: "Why are they all strung together?" Because the feed was one continuous scroll of hairline-separated cards, so reading a piece meant watching the next one slide halfway into frame, and a long piece pushed its own footer off screen. It's now a deck: **each piece fills the viewport**, its meta row pinned above and its triage row and footer pinned below, with only the text moving in between. Running off the end of a long piece chains outward and snaps to the next one (`scroll-snap-type: y mandatory`, `scroll-snap-stop: always` so a fast flick can't skip one). The meta row carries a `3/12` locator; "Show more" is gone along with the fold it existed for, since a long piece now scrolls inside its own page. **Live markdown while typing**: a highlighted copy of the piece's text is painted directly behind the textarea (new `src/lib/markdown-highlight.ts` + `live-markdown-textarea.tsx`) with headings gold, bold/italic/code/links styled, and the `##`/`**`/`>`/bullet markers dimmed but still on screen. Two invariants keep that honest, both tested: `highlightMarkdown` never changes a character (stripping its spans returns the source exactly, so it's a highlighter and not a renderer), and no `.md-*` rule may change a glyph's advance width, because the caret still belongs to the transparent textarea on top and would drift off text that laid out differently. Faux weight is a `text-shadow`, never `font-weight`. That's what keeps native undo, spellcheck, IME and byte-exact whitespace, and it's why short-form still isn't Tiptap: a document model round-trips the text, and a tweet spaced on purpose comes back rewritten. A piece that wants a document model has **Make it a draft**. Finally, the idea workspace now mirrors the feed through `focusedPieceId` / `hoveredPieceId` in app-store: the focused piece gets the gold rail in the panel, and hovering a card lights up its row (both directions).

**Verification**: 30 new tests, most of them the round-trip invariant across headings, emphasis, code, links, images, lists, quotes, rules, unmatched markers, trailing whitespace, HTML-ish text and emoji; 536 passing with the same 22 pre-existing `api-*` failures (ARI-132); `tsc --noEmit` and `npm run build` clean. Driven in a browser: two pages measured exactly the container height (814px), a 40-paragraph piece scrolled 1389px inside its own page while the page itself did not move at all, and the mirror was compared character by character against an unstyled copy of the same text — 262 of 262 characters within 0.14px horizontally and 0px vertically, which is the caret-drift test.

## 2026-07-26 - Idea workspace: a second column for what's inside the idea you're in (ARI-174)

## 2026-07-26 - Delivery preflight: agents stop reporting success for pushes the app can never import

**Commit**: on `feat/mcp-delivery-preflight` (PR #4)

**Summary**: A push that lands on disk is not a push the user will ever see, and fragment-mcp had no way to tell the difference. Real-world failure that prompted this: the agent-inbox gate refuses a request whose `Host` is not localhost, so a browser opening the app over a tailnet name got 404 while a localhost probe got 200; nine pieces accumulated in `~/.fragment/inbox` over 27 hours with every push reporting success. (The gate-side fix is the separate `FRAGMENT_INGRESS_ALLOWED_HOSTS` change, PR #3.) New `packages/fragment-mcp/src/delivery-check.ts` answers "if I push now, will it arrive?" by probing the running app and scanning the inbox. It probes the origin the human actually opens (`FRAGMENT_APP_ORIGIN`) as a real request rather than spoofing a `Host` header on the local URL, because undici drops a manually set `Host` and a header-spoofed probe silently tests localhost and passes while the browser is being refused. Three states: `ok`, `app_down` (queueing is legitimate, the app is just closed), and `ingress_blocked` (misconfiguration, nothing will ever import). New `fragment-mcp doctor` prints the full report and exits nonzero when delivery is broken; `fragment-mcp push` and the `create_idea` / `add_piece` MCP tools refuse outright on `ingress_blocked` rather than returning a success the user will never see. Documented in AGENT-API.md.

**Verification**: classification matrix extracted pure (`classifyDelivery`) and unit-tested; package suite 28 passing; `tsc --noEmit` clean; esbuild bundle green. Doctor exercised live on olympus against the real tailnet origin (200, ok, honest backlog report), an unreachable host (app_down), a second instance with ingress unset (404, ingress_blocked, exit 1), and a bogus port (app_down). Push blocking verified both ways: refused with remediation text while ingress was closed, queued normally against the live app.
